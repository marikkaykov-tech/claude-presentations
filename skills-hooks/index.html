02
Skills · Anatomy

A skill is just a folder with a SKILL.md

pdf-tools/
├── SKILL.md  ← required
├── reference.md  ← loaded on demand
└── scripts/
    └── fill_form.py

Only the name + description sit in context all the time. The body and extra files are read only when Claude decides the skill is relevant — that's why you can install dozens without bloating the prompt.

pdf-tools/SKILL.md
---
name: pdf-tools
description: Extract text, fill forms and merge
  PDFs. Use when the user mentions a .pdf
  file or asks to work with PDF documents.
---

# PDF tools

## Extract text
Use pdfplumber: ...

## Fill a form
Run `python scripts/fill_form.py in.pdf data.json`

For advanced cases see [reference.md](reference.md).

Skills · Installation

Three common ways to install a skill

1 · Plugin marketplace recommended

Add a marketplace once, then install plugins from it. Updates are handled for you.

# inside Claude Code
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

# or browse interactively
/plugin

2 · Copy the folder

Every skill is just files — clone or download and drop it in a skills directory.

# personal (all projects)
git clone https://github.com/anthropics/skills
cp -r skills/skills/pdf ~/.claude/skills/

# project (shared via git)
cp -r skills/skills/pdf .claude/skills/

Restart Claude Code so it picks the new skill up.

3 · Skills CLI

Cross-agent installer from the skills.sh directory (Claude Code, Cursor, Codex…).

npx skills add vercel-labs/agent-skills

Or write your own: create .claude/skills/my-skill/SKILL.md — or ask Claude to use skill-creator.

Hooks · Events

Hooks fire at points in Claude's lifecycle

SessionStart

Session opens/resumes — inject context (git status, TODOs).

UserPromptSubmit

Before your prompt reaches Claude — validate or add context.

PreToolUse

Before a tool runs — the main place for guardrails.

PermissionRequest

When a permission dialog would show — auto-allow or deny.

PostToolUse

After a tool succeeds — format, lint, test.

Notification

Claude needs input or permission — ping yourself.

Stop / SubagentStop

Claude finishes — run checks, force it to keep going.

PreCompact

Before context is compacted — back up the transcript.

SessionEnd

Session closes — cleanup, logging, stats.

Each hook receives a JSON payload on stdin (session id, tool name, tool input…). Exit code 0 = OK, 2 = block and send stderr back to Claude as feedback.
08
Hooks · Anatomy

A hook is config in settings.json

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [                // event
      {
        "matcher": "Edit|Write",      // which tools
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path'
              | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}

Event

Which lifecycle moment — PreToolUse, Stop, …

Matcher

Regex on the tool name: Bash, Edit|Write, mcp__github__.*. Empty = everything.

Command

Any shell command or script. Reads JSON from stdin, answers with an exit code (and optionally JSON on stdout).

Settings files, by scope:
~/.claude/settings.json — you, everywhere
.claude/settings.json — the project (commit it)
.claude/settings.local.json — you, this project only
09
Hooks · Widely used

The hooks almost everyone ends up writing

✨ Auto-format on edit

PostToolUse · Edit|Write

Run Prettier, Black, gofmt or ruff on every file Claude touches.

🛑 Block dangerous commands

PreToolUse · Bash

Reject rm -rf, git push --force, DROP TABLE with exit code 2.

🔒 Protect sensitive files

PreToolUse · Edit|Write|Read

Keep Claude out of .env, keys, lock files and .git/.

🔔 Desktop notification

Notification / Stop

Sound or toast when Claude is waiting for you or done — so you can walk away.

✅ Lint / test before "done"

Stop · or PostToolUse

Run tsc, eslint or the test suite; exit 2 makes Claude fix failures.

🧭 Inject context at start

SessionStart / UserPromptSubmit

Print git branch, open issues or today's tasks — stdout is added to Claude's context.

Hooks · Copy-paste examples

Two ready-to-use hooks

Block rm -rf · .claude/hooks/guard.sh
#!/usr/bin/env bash
cmd=$(jq -r '.tool_input.command')

if echo "$cmd" | grep -qE 'rm -rf|git push --force'; then
  echo "Blocked: dangerous command" >&2
  exit 2   # block + tell Claude why
fi
exit 0
{ "hooks": { "PreToolUse": [{
  "matcher": "Bash",
  "hooks": [{ "type": "command",
    "command": "bash .claude/hooks/guard.sh" }]
}]}}
Notify when Claude needs you · settings.json
{ "hooks": { "Notification": [{
  "matcher": "",
  "hooks": [{ "type": "command",
    // Windows
    "command": "powershell -c [console]::beep(800,300)"
    // macOS: osascript -e 'display notification \"Claude needs you\"'
    // Linux: notify-send 'Claude Code' 'Needs your input'
  }]
}]}}
Tip: inside Claude Code run /hooks to see every active hook and where it's defined — or just ask Claude "add a hook that…" and it will edit settings.json for you.

Hooks · Installation

How hooks are usually installed

Paste into a settings file

The most common way: copy a JSON snippet into ~/.claude/settings.json (personal) or .claude/settings.json (team). Keep longer scripts in .claude/hooks/.

Use the /hooks menu

Interactive UI inside Claude Code — pick an event, a matcher and a command; it writes the JSON for you.

Install a plugin that ships hooks

Plugins can include hooks/hooks.json. /plugin install … activates them alongside skills, commands and agents — e.g. Superpowers uses a SessionStart hook to load its skills intro.

Review & restart

Hooks are snapshotted at startup — restart the session (or review in /hooks) after edits.

Before you install

Treat skills & hooks like code you run

⚠️ Hooks run with your permissions

A hook is an arbitrary shell command that runs automatically — no confirmation prompt. A malicious one can read files, exfiltrate secrets or delete things.

⚠️ Skills can carry scripts & instructions

A skill's text steers Claude, and its scripts may get executed. Read the SKILL.md and any scripts/ before trusting it.

✅ Good habits

  • Prefer official / well-known sources with many stars
  • Read the code; pin to a commit or tag
  • Quote shell variables, use absolute paths in hooks

✅ Keep it lean

  • Install what you'll use — descriptions cost context
  • Write clear descriptions so skills trigger at the right time
  • Check /hooks and /plugin periodically
