01 · Basics

How slash commands work

A slash command is an instruction to Claude Code itself, not a message to the model. Type / at the start of the prompt and a menu opens.

  1. Type /

    An autocomplete list appears with every available command and a short description.

  2. Filter by typing

    Type /com and the list narrows to /compact, /config, and so on. Use ↑ ↓ and Tab to pick one.

  3. Add arguments

    Many commands take text after them, for example /compact focus on the auth bug.

  4. Press Enter

    The command runs right away. Some open an interactive panel you leave with Esc.

# Start Claude Code in your project folder $ cd my-project $ claude # Inside the session > /help ← list every command > /model ← opens a picker > /compact keep the API notes ← command + argument
Three kinds of commands: built-in ones (shipped with Claude Code), custom ones you write in .claude/commands/, and ones added by plugins and MCP servers.

02 · Getting started

The first commands in a new project

Run these once when you open a project for the first time.

/init

Scans the codebase and writes a CLAUDE.md file describing the project: its structure, build and test commands, and conventions. Claude reads this file at the start of every session.

When: the first time you use Claude Code in a repository.
/login · /logout

Sign in with your Claude account or API key, or sign out. Use these to switch between accounts, for example personal and work.

When: first launch, or when changing accounts.
/help

Lists every command available in the current session, including your custom and plugin commands.

When: whenever you forget a command name.
/terminal-setup

Sets up Shift+Enter for new lines in terminals that need it, such as VS Code's terminal, so you can write multi-line prompts.

When: Shift+Enter sends the message instead of adding a line.

03 · Session

Managing the conversation

A long session fills Claude's context window. These commands start fresh, shrink, rewind, or resume a conversation.

/clear

Wipes the conversation history. CLAUDE.md and your settings stay. The cleanest way to begin an unrelated task.

When: switching to a new task. Old context only distracts.
/compact [instructions]

Replaces the history with a summary so you keep working with room to spare. Add text to say what the summary must keep.

> /compact keep the DB schema and open TODOs
/resume

Opens a list of past conversations in this project so you can continue one. From the shell, claude --continue reopens the latest.

When: picking up yesterday's work.
/rewind

Goes back to an earlier point in the conversation and can undo the file changes Claude made after it. Pressing Esc twice opens the same menu.

When: Claude went the wrong way and you want to try again.
/export

Saves the current conversation to a file or copies it to the clipboard, for notes, docs, or sharing with a teammate.

/exit

Quits Claude Code. Pressing Ctrl+C twice does the same.

04 · Context & cost

Knowing where you stand

Check these before the context window fills or you reach a usage limit.

/context

Shows a chart of what fills the context window: system prompt, tools, MCP servers, memory files, and messages.

When: answers get worse, or you want to know which MCP server takes the most space.
/cost

Token usage and estimated spend for the current session. Most useful when you pay per token with an API key.

/usage

Shows how much of your plan's limits you have used and when they reset (Pro and Max subscriptions).

/status

Version, signed-in account, current model, working directory, and connection status, all on one screen.

Rule of thumb: when /context shows the window is mostly full, run /compact if the task continues, or /clear if a new task starts.

05 · Memory

Teaching Claude about your project

Memory is plain Markdown that Claude loads at the start of each session. Store your rules there once instead of repeating them.

/memory

Opens your memory files in an editor. You choose which one:

FileScope
./CLAUDE.mdThis project, shared with the team in git
./CLAUDE.local.mdThis project, only you (add it to .gitignore)
~/.claude/CLAUDE.mdAll your projects
# CLAUDE.md example # My Shop API ## Commands - Run dev server: npm run dev - Run tests: npm test ## Rules - Use TypeScript, never plain JS - Every new endpoint needs a test - Do not edit files in /legacy
Tip: keep CLAUDE.md short and specific. Claude follows "Run npm test before committing" better than "write good code".

06 · Configuration

Making Claude Code yours

/model

Switch models mid-session: Opus for hard reasoning, Sonnet for everyday coding, Haiku for fast, simple tasks.

> /model sonnet
/config

Opens the settings panel: theme, auto-compact, notifications, editor mode, and more.

/permissions

Sets which tools Claude may use without asking, for example allowing npm test and always asking before git push.

When: you approve the same harmless command over and over.
/statusline

Creates a custom status bar under the prompt showing model, git branch, context use, or anything a script prints.

/vim

Turns on Vim keybindings for editing the prompt (normal and insert modes). Run it again to turn them off.

/add-dir

Lets Claude work in another folder too, such as a shared library next to your app.

> /add-dir ../shared-utils

07 · Extending

Agents, tools, hooks & plugins

These commands connect Claude Code to more tools and automate parts of your workflow.

/mcp

Manages MCP servers, which give Claude new tools such as databases, browsers, GitHub, or Figma. Shows status, lets you sign in, and lists each server's tools.

# add one from the shell first $ claude mcp add github ... # then inside Claude > /mcp
/agents

Creates and edits subagents: helpers with their own instructions, tools, and context, such as a "test-writer" or "code-reviewer".

When: a task repeats and needs a focused specialist.
/hooks

Sets up shell commands that run automatically on events, such as running Prettier after every file edit or blocking edits to .env.

When: something must always happen, without relying on Claude remembering it.
/plugin

Browse, install, and manage plugins, which bundle commands, agents, hooks, and MCP servers into one install.

/ide

Connects to VS Code or JetBrains so Claude sees your open file and selection, and shows diffs in the editor.

/install-github-app

Sets up the Claude GitHub app so you can mention @claude in issues and pull requests.

08 · Code quality

Reviewing code before you ship

/code-review [level]

Reviews your current changes or a pull request for bugs. The level (low, medium, high, ...) sets how deep it goes. --fix applies the fixes it finds.

> /code-review high > /code-review 42 --comment
/security-review

Checks pending changes for security problems: injection, leaked secrets, unsafe authentication, and similar issues.

When: before merging anything that handles user input or credentials.
/simplify

Looks over the changed code for duplication and needless complexity, then makes the cleanups.

/pr-comments

Fetches the review comments on a GitHub pull request so Claude can address them one by one.

Workflow: write the feature → /code-review → fix → /security-review → ask Claude to commit and open a pull request.

09 · Diagnostics

When something isn't working

/doctor

Checks your installation: version, install method, settings files, and other common problems. Run this first when something breaks.

/bug · /feedback

Sends a bug report or feedback to Anthropic, with the option to include the conversation.

/release-notes

Shows what changed in recent versions. Worth a look after an update.

/status

Confirms which account, model, and directory you're using. It answers most "why is it behaving like that?" questions.

Troubleshooting order: /status → /doctor → /mcp (if a tool is missing) → /context (if answers got worse).

10 · Custom commands

Write your own slash commands

Any Markdown file in a commands folder becomes a slash command. The file's text is the prompt Claude receives.

  1. Create the folder

    .claude/commands/ in the project (shared with the team), or ~/.claude/commands/ (only you, all projects).

  2. Add a .md file

    The file name becomes the command name: fix-issue.md → /fix-issue.

  3. Use $ARGUMENTS

    Whatever you type after the command replaces $ARGUMENTS. $1, $2 pick out single arguments.

  4. Run it

    /fix-issue 123. Commit the folder so the whole team gets the command.

# .claude/commands/fix-issue.md --- description: Fix a GitHub issue end to end allowed-tools: Bash(gh:*), Edit, Read --- Fix GitHub issue #$ARGUMENTS. 1. Run `gh issue view $ARGUMENTS` 2. Find the relevant code 3. Write a failing test first 4. Implement the fix 5. Run the tests and show results
Frontmatter (between the --- lines) is optional. description shows in the / menu, and allowed-tools sets what the command may run without asking.

12 · Walkthrough

Putting it together on a real project

One feature from start to finish, using the commands in the order you'd actually reach for them.

  1. Open & orient

    claude in the repo → /init to create CLAUDE.md → read it and fix anything wrong.

  2. Plan

    Press Shift+Tab into plan mode and describe the feature. Claude explores the code and proposes a plan without editing anything.

  3. Build

    Approve the plan. Use @file to point at key files and ! npm test to run tests yourself.

  4. Stay lean

    Check /context. If it's getting full, /compact keep the plan and failing tests.

  5. Review & ship

    /code-review → /security-review → "commit and open a PR".

  6. Reset

    /clear before the next, unrelated task.

$ cd todo-app && claude > /init ✓ Created CLAUDE.md [Shift+Tab → plan mode] > Add due dates to tasks, with a date picker and overdue highlight Plan: 1) migration 2) API field 3) UI picker 4) tests [approve] > ! npm test ✓ 48 passed > /context Messages ████████░░ 78% > /compact keep the migration notes > /code-review 1 finding: missing timezone check > fix that, then commit and open a PR > /clear
