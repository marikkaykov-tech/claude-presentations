Syntax

Defining a class

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        return f"{self.name} says woof"

rex = Dog("Rex", 3)
print(rex.bark())
  • class Name: starts a class (CamelCase)
  • __init__ runs automatically on creation
  • self = the object itself; always the first parameter
  • self.name = ... creates an attribute
  • Dog(...) builds an object; no new
Syntax

Instance vs. class attributes

class Dog:
    species = "Canine"      # class attr
    count = 0

    def __init__(self, name):
        self.name = name    # instance attr
        Dog.count += 1

a = Dog("Rex")
b = Dog("Luna")
print(Dog.count)   # 2
print(a.species)   # Canine
  • Instance attribute: each object has its own copy (set via self.)
  • Class attribute: one value shared by all objects (set in the class body)
  • Change a shared value through the class: Dog.count
Syntax

Methods and printing

class Rectangle:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h

    def __str__(self):
        return f"Rect({self.w}x{self.h})"

r = Rectangle(3, 4)
print(r.area())   # 12
print(r)          # Rect(3x4)
  • Call a method: obj.method(); Python passes self for you
  • Inside the class, reach other members with self.
  • __str__ controls what print(obj) shows
  • Without it you get <Rectangle object at 0x...>
Worked example

A Stack class

class Stack:
    def __init__(self):
        self.items = []

    def push(self, x):
        self.items.append(x)

    def pop(self):
        return self.items.pop()

    def is_empty(self):
        return len(self.items) == 0

s = Stack()
s.push(1); s.push(2)
print(s.pop())       # 2
print(s.is_empty())  # False
  • The list is the data; push/pop/is_empty are the behavior
  • The caller never touches items directly
  • Each Stack() has its own list, because it is created in __init__
  • Same pattern fits Queue, Playlist, Cart, Inventory

Student with an average

  • Class Student with name and a list marks
  • Method average() returns the mean of the marks
  • Method add_mark(m) appends a mark
s = Student("Dana", [80, 90])
s.add_mark(100)
print(s.average())

90.0

Solution 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def add_mark(self, m):
        self.marks.append(m)

    def average(self):
        return sum(self.marks) / len(self.marks)
Exercise 3 · classes

Bank account

  • BankAccount(owner, balance=0)
  • deposit(amount) and withdraw(amount)
  • Withdrawing more than the balance must not change it; print "Insufficient funds"
  • Add __str__: Dana: 150
acc = BankAccount("Dana", 100)
acc.deposit(100)
acc.withdraw(500)
print(acc)

Insufficient funds · Dana: 200

Solution 
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Insufficient funds")
        else:
            self.balance -= amount

    def __str__(self):
        return f"{self.owner}: {self.balance}"

Syntax

Encapsulation

class Account:
    def __init__(self, balance):
        self._balance = balance   # "internal"
        self.__pin = 1234         # name-mangled

    @property
    def balance(self):            # getter
        return self._balance

    @balance.setter
    def balance(self, value):     # setter
        if value < 0:
            raise ValueError("negative")
        self._balance = value

acc = Account(50)
acc.balance = 80      # setter runs
acc.balance = -5      # ValueError
  • _x: convention, "please don't touch"
  • __x: Python renames it to _Account__x
  • @property: use it like an attribute, run code behind it
  • @x.setter: validate on assignment
Exercise 5 · encapsulation

Safe thermostat

  • Class Thermostat, starting at 20
  • Temperature must stay between 5 and 35
  • Anything else raises ValueError("Temp must be 5-35")
  • Use a property with a setter, and validate in the constructor too
t = Thermostat()
t.temp = 25      # fine
t.temp = -500    # ValueError
Solution 
class Thermostat:
    def __init__(self, temp=20):
        self.temp = temp          # goes through the setter

    @property
    def temp(self):
        return self._temp

    @temp.setter
    def temp(self, value):
        if not 5 <= value <= 35:
            raise ValueError("Temp must be 5-35")
        self._temp = value
Syntax · the @ symbol

Decorators: what is @?

@decorator
def f():
    ...

# means exactly the same as:
def f():
    ...
f = decorator(f)
  • A decorator wraps a function or method and changes how it behaves
  • It sits on the line directly above the def
  • In OOP you will mostly use the built-in ones below
DecoratorWhat it does
@propertymethod read like an attribute: obj.x
@x.setterruns on obj.x = value
@staticmethodno self; a plain function inside the class
@classmethodgets the class (cls) instead of the object
@abstractmethodchildren must implement it
@dataclassauto-writes __init__, __repr__, __eq__
Syntax · @staticmethod, @classmethod

Three kinds of methods

class Person:
    count = 0

    def __init__(self, name, age):
        self.name = name
        self.age = age
        Person.count += 1

    def greet(self):                 # instance method
        return f"Hi, I'm {self.name}"

    @classmethod
    def from_string(cls, text):      # alt. constructor
        name, age = text.split("-")
        return cls(name, int(age))

    @staticmethod
    def is_adult(age):               # no self, no cls
        return age >= 18

p = Person.from_string("Dana-25")
print(Person.is_adult(p.age))        # True
  • Instance method: first parameter self, works on one object
  • @classmethod: first parameter cls, works on the class; great for alternative constructors
  • @staticmethod: no special first parameter; a helper that belongs to the class by topic
  • Call the last two on the class: Person.is_adult(20)
Exercise · decorators

Temperature helper

  • Class Temperature with a celsius attribute
  • @classmethod from_fahrenheit(cls, f) returns a new Temperature
  • @staticmethod is_freezing(c) returns c <= 0
  • @property fahrenheit computes c * 9/5 + 32
t = Temperature.from_fahrenheit(212)
print(t.celsius, t.fahrenheit)
print(Temperature.is_freezing(-3))

100.0 212.0 · True

Solution 
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f):
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_freezing(c):
        return c <= 0

    @property
    def fahrenheit(self):
        return self.celsius * 9 / 5 + 32
Syntax · @dataclass

Less boilerplate with dataclasses

from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int = 0

p = Point(3)
print(p)              # Point(x=3, y=0)
print(p == Point(3))  # True
  • List fields with type hints; Python writes __init__, __repr__ and __eq__
  • Defaults work like in functions
  • Best for classes that mostly just hold data
  • You can still add your own methods
Syntax

Inheritance

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed

    def speak(self):          # override
        return "Woof"

d = Dog("Rex", "Lab")
print(d.name, d.speak())
  • class Child(Parent):
  • Child gets all parent attributes and methods
  • super().__init__(...) runs the parent setup
  • Define the same method name to override
  • Use for "is-a": a Dog is an Animal
Syntax

Checking types

d = Dog("Rex", "Lab")

type(d).__name__          # 'Dog'
isinstance(d, Dog)        # True
isinstance(d, Animal)     # True  (a Dog is an Animal)
issubclass(Dog, Animal)   # True
isinstance(Animal("x"), Dog)   # False
  • isinstance(obj, Class) also accepts subclasses; type(obj) == Class does not
  • Prefer isinstance over comparing types
Exercise 6 · inheritance

Media library

  • Base class Media(title, year) with info() returning "Title (year)"
  • Book adds author; DVD adds minutes
  • Each overrides info() and reuses the parent's with super()
print(Book("Dune", 1965, "Herbert").info())
print(DVD("Alien", 1979, 117).info())

Dune (1965) by Herbert · Alien (1979), 117 min

Solution 
class Media:
    def __init__(self, title, year):
        self.title, self.year = title, year
    def info(self):
        return f"{self.title} ({self.year})"

class Book(Media):
    def __init__(self, title, year, author):
        super().__init__(title, year)
        self.author = author
    def info(self):
        return super().info() + f" by {self.author}"

class DVD(Media):
    def __init__(self, title, year, minutes):
        super().__init__(title, year)
        self.minutes = minutes
    def info(self):
        return super().info() + f", {self.minutes} min"

Polymorphism

class Dog:
    def speak(self): return "Woof"

class Cat:
    def speak(self): return "Meow"

class Robot:               # not an Animal!
    def speak(self): return "Beep"

for x in [Dog(), Cat(), Robot()]:
    print(x.speak())
  • Same method name, different behavior per class
  • The caller doesn't check the type, it just calls speak()
  • Python is duck typed: if it has speak(), it works
  • Adding a new class needs no change to the loop
Exercise 8 · polymorphism

Shapes and total area

  • Circle(r), Square(side), Triangle(base, height)
  • Each has its own area()
  • Write total_area(shapes) that works for any mix, with no if/elif on type
print(total_area([Square(2), Triangle(4, 3)]))

10.0

Solution 
import math

class Circle:
    def __init__(self, r): self.r = r
    def area(self): return math.pi * self.r ** 2

class Square:
    def __init__(self, s): self.s = s
    def area(self): return self.s ** 2

class Triangle:
    def __init__(self, b, h): self.b, self.h = b, h
    def area(self): return 0.5 * self.b * self.h

def total_area(shapes):
    return sum(s.area() for s in shapes)
Exercise 9 · polymorphism

Employee pay

  • Employee(name) base class with pay()
  • FullTime(name, salary): pays salary
  • PartTime(name, hours, rate): pays hours * rate
  • Print every employee's pay from one loop
staff = [FullTime("Dan", 5000), PartTime("Eli", 40, 30)]
for e in staff:
    print(e.name, e.pay())

Dan 5000 · Eli 1200

Solution 
class Employee:
    def __init__(self, name): self.name = name
    def pay(self): raise NotImplementedError

class FullTime(Employee):
    def __init__(self, name, salary):
        super().__init__(name); self.salary = salary
    def pay(self): return self.salary

class PartTime(Employee):
    def __init__(self, name, hours, rate):
        super().__init__(name); self.hours, self.rate = hours, rate
    def pay(self): return self.hours * self.rate

Abstraction with ABC

from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount): ...

class Card(Payment):
    def pay(self, amount):
        return f"Charged {amount}"

Payment()   # TypeError
Card().pay(50)

  • A child that skips an @abstractmethod can't be created either
Exercise 11 · abstraction

Payment methods

  • Abstract Payment with pay(amount)
  • Card, PayPal, Cash implement it with different messages
  • What happens if Cash forgets to implement pay?
Solution 
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount): ...

class Card(Payment):
    def pay(self, amount): return f"Card: {amount}"
class PayPal(Payment):
    def pay(self, amount): return f"PayPal: {amount}"
class Cash(Payment):
    def pay(self, amount): return f"Cash: {amount}"

Missing it → TypeError: Can't instantiate abstract class Cash when you create Cash().

Syntax · class inside a class

Nested (inner) classes

class Computer:
    class CPU:                      # inner class
        def __init__(self, cores):
            self.cores = cores

        def info(self):
            return f"{self.cores} cores"

    def __init__(self, name, cores):
        self.name = name
        self.cpu = self.CPU(cores)  # create inner object

pc = Computer("Dell", 8)
print(pc.cpu.info())                # 8 cores

c = Computer.CPU(4)                 # also possible
print(type(c).__name__)             # CPU
  • Define a class in the body of another class
  • Reach it with Outer.Inner or self.Inner
  • The inner class does not get the outer object automatically; pass it in if needed
  • Use it when the inner class only makes sense inside the outer one (a Node inside a LinkedList)
  • If other code needs it too, define it at the top level instead
Syntax · class inside a class

Example: LinkedList with an inner Node

class LinkedList:
    class Node:
        def __init__(self, value):
            self.value = value
            self.next = None

    def __init__(self):
        self.head = None

    def add(self, value):
        node = self.Node(value)
        node.next = self.head
        self.head = node

    def show(self):
        cur = self.head
        while cur:
            print(cur.value)
            cur = cur.next

ll = LinkedList()
ll.add(1); ll.add(2)
ll.show()          # 2, then 1
  • Node is an implementation detail of LinkedList, so it lives inside
  • Users call ll.add(5) and never build Nodes themselves
  • Nested class vs composition: composition stores an object of a class defined elsewhere; nesting also defines the class in place
Exercise · nested class

Pizza with Toppings

  • Class Pizza(size) with an inner class Topping(name, price)
  • add_topping(name, price) creates a Topping inside and stores it in a list
  • total() returns base price (30) plus the sum of topping prices
p = Pizza("large")
p.add_topping("olives", 5)
p.add_topping("corn", 3)
print(p.total())

38

Solution 
class Pizza:
    class Topping:
        def __init__(self, name, price):
            self.name = name
            self.price = price

    def __init__(self, size):
        self.size = size
        self.toppings = []

    def add_topping(self, name, price):
        self.toppings.append(self.Topping(name, price))

    def total(self):
        return 30 + sum(t.price for t in self.toppings)
Exercise · combine everything

Product and Inventory

  • Product(name, price, qty) with a property price that rejects negatives
  • total_value() returns price * qty
  • Inventory holds a list of products: add(p), total(), __len__
  • @classmethod Product.from_string("milk,5,10")
inv = Inventory()
inv.add(Product.from_string("milk,5,10"))
inv.add(Product("eggs", 2, 30))
print(len(inv), inv.total())

2 110.0

Solution 
class Product:
    def __init__(self, name, price, qty):
        self.name, self.qty = name, qty
        self.price = price

    @property
    def price(self): return self._price
    @price.setter
    def price(self, v):
        if v < 0: raise ValueError("negative price")
        self._price = v

    def total_value(self): return self.price * self.qty

    @classmethod
    def from_string(cls, text):
        n, p, q = text.split(",")
        return cls(n, float(p), int(q))

class Inventory:
    def __init__(self): self.products = []
    def add(self, p): self.products.append(p)
    def total(self): return sum(p.total_value() for p in self.products)
    def __len__(self): return len(self.products)
